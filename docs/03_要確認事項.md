設計書「**sample_Windows詳細設計書.xlsx**」（シート「1.概要」「8.ファイルサーバ」）を
Ansible 化するにあたり、**記載が無い／マスクされている／矛盾している／実行前に確定が必要**
な項目を整理したものです。

区分の凡例:

- **A（実行前に必須）** … 値が確定しないと構築できない、または誤った設定になる

- **C（参考）** … 動作に影響しうる留意事項

## B. 実装判断あり

### B-1. 仮想メモリ（ページングファイル）の記載が矛盾している

シート8「5.ｼｽﾃﾑのﾌﾟﾛﾊﾟﾃｨ」の記載:

| 項目 | 設計書の値 |
| --- | --- |
| すべてのドライブのページングファイルのサイズを自動的に管理する | □（オフ） |
| C:[Windows] | ● ページングファイルなし |
| D:[ボリューム] | ● ページングファイルなし |
| 総容量（MB） | 1280 |
| 現在の割り当て | 1920MB |

全ドライブが「ページングファイルなし」であれば総容量は 0MB になるはずで、
**1280MB / 1920MB という記載と矛盾**します（実機のスクリーンショットを転記した際の
チェック位置ずれの可能性があります）。

**現状の実装**: 既定では**ページングファイルを変更しません**
（`pagefile_configure: false`）。OS 既定（自動管理）のままとなります。

**→ 自動管理のままとするか、C: にシステム管理サイズを設定するかをご確認ください。**

### B-2. ファイアウォールの記載が矛盾している

シート8「3.ｻｰﾊﾞｰﾏﾈｰｼﾞｬｰ」の Windows Defender ファイアウォール欄では、
パブリック/プライベート/ドメインの 3 プロファイルとも
**「無効」と「有効」の両方に ●** が付いています。

概要 1.10 の本文「ファイアウォールは Azure NSG で制御するため、無効にする」を採用し、
**3 プロファイルすべて無効**として実装しています（`firewall_state: disabled`）。

なお、ログ設定（パス / サイズ 4096KB / 破棄パケット記録なし / 正常接続記録なし /
通知なし）は無効化の前に明示的に設定しています。

**ファイルサーバ固有の留意点**: ファイアウォールを無効にするため、
FTP（21/tcp）およびパッシブモードのデータポート範囲は **Azure NSG 側で許可**が必要です。
`win_ftp` ロールは念のため受信規則も作成しますが、無効時は効果がありません
（概要 1.10 のとおり NSG 設定は別紙参照のため未入手）。

### B-3. 「自動更新を構成する = 無効」のレジストリ解釈

概要 1.14 / シート8「15.ローカルグループポリシー」は、
「コンピューターの構成 > 管理用テンプレート > Windowsコンポーネント > Windows Update >
自動更新を構成する」を **無効** に設定する、としています。

グループポリシーの「無効」は、レジストリ上は
`HKLM:\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU\NoAutoUpdate = 1`
（＝自動更新を行わない）に対応します。本文の「更新プログラムは確認しないため」という
意図と一致するため、この設定で実装しています（併せて `AUOptions = 2`）。

**→ 「更新プログラムを自動的にダウンロード・インストールさせない」という理解で
相違ないかご確認ください。**

### B-4. タスクスケジューラの実行ユーザ「Administrator」の所属

概要 1.13 の実行ユーザは全 8 件「Administrator」ですが、
**ローカルの Administrator かドメインの Administrator か**が明記されていません。
ファイルサーバはドメイン参加サーバのため、どちらも指定しえます。

現状は `vault_task_run_user` で指定する実装とし、既定値を
`Administrator`（ローカル）としています。

**→ `PICKLES-CORP\Administrator` とすべきかご確認ください。**

### B-5. FTP の 2 サイトが同一ポート(21)を共有する

概要 1.16 の 2 サイトはいずれも `*:21` にバインドし、
No.1 は仮想ホスト名なし、No.2 は `NPJS.com` です。

IIS FTP で同一ポートに複数サイトを共存させる場合、クライアント側は
`ユーザー名` の代わりに `NPJS.com|ユーザー名` の形式で接続する必要があります
（FTP 仮想ホスト名の仕様）。

**→ 現行環境でクライアントがどのようにログオンしているかをご確認ください。**
併せて、FTP 認証ユーザのアクセス許可「読み取り、書き込み」は **FTP の承認規則**として設定し、
NTFS 側は物理パスに `Modify` を付与しています。

### B-6. Windows Defender の記載が矛盾している

シート8 の記載が 2 か所で食い違っています。

| 箇所 | 記載 |
| --- | --- |
| 3.ｻｰﾊﾞｰﾏﾈｰｼﾞｬｰ「Windows Defender」 | リアルタイム保護 = **有効** |
| 15.ローカルグループポリシー | 「Microsoft Defender ウイルス対策を無効にする」= **有効**（＝ Defender 無効化） |
| 12.役割と機能 | 「Microsoft Defender ｳｲﾙｽ対策」= ■（ﾃﾞﾌｫﾙﾄ） |

概要 1.11「セキュリティソフト（Cortex）を導入するため、Windows Defender はグループポリシーにて
手動で無効化する」に従い、**ローカル GPO で無効化**する実装としています
（`HKLM:\SOFTWARE\Policies\Microsoft\Windows Defender\DisableAntiSpyware = 1`）。
3. の「リアルタイム保護 = 有効」は Cortex 導入前の実機状態を転記したものと解釈しています。

ただし Windows Server 2022 / 2025 では **改ざん防止（Tamper Protection）** が有効な場合、
このポリシーが無視されることがあります。シート8「16.ｻｰﾋﾞｽ一覧」の特記事項にある
「グループポリシー設定により、スタートアップの種類が Manual に変更」された状態になるか、
`playbooks/99_verify.yml` の証跡で確認してください。

**→ Cortex XDR 導入時に Defender が自動的に無効化される想定であれば、
本設定は不要となる可能性があります。**

### B-7. IIS の役割は「ベンダー様対応」ではないか（新規）

概要 1.9 の表では、No.7（ファイルサーバ）の「※下記はアプリベンダー様にて対応いただく想定です」欄は
**「-」**（記載なし）で、追加する役割は **FSRM / FTP** のみとなっています。

一方、シート8「12.役割と機能の追加」では **Web サーバー (IIS) の各機能が ■** です。

FTP サーバーは IIS の一部であり FTP の導入に IIS 基盤が必要なため、
シート8 の詳細（IIS ■）を採用し、`windows_features` に IIS 一式を含めています。

**→ IIS の各機能（HTTP エラー / ディレクトリの参照 / 静的なコンテンツ / HTTP ログ等）を
Ansible で導入してよいか、ベンダー様対応範囲かをご確認ください。**

### B-8. FSRM の具体的な設定内容が未記載（新規）

概要 1.9 / シート8 12. で **ファイル サーバー リソース マネージャー (FSRM)** の
役割追加は指定されていますが、**クォータ・ファイルスクリーン・記憶域レポート・
ファイル分類などの具体的な設定は設計書に記載がありません**。

**現状の実装**: 役割と管理ツール（`FS-Resource-Manager` / `RSAT-FSRM-Mgmt`）の
**導入のみ**を行い、FSRM の設定は行いません。

**→ クォータ等の設定が必要な場合は、設定内容をご提供ください
（別紙がある場合はそちらもご共有ください）。**

### B-9. 共有フォルダの設定が未記載（新規）

「ファイルサーバ」という用途（シート8 1.基本情報）に対し、
**SMB 共有フォルダの構成（共有名・パス・共有アクセス許可・NTFS アクセス許可）が
設計書に記載されていません**。D: 配下で明示されているのは FTP の物理パス
（`D:\POD` / `D:\NPJS`）とタスクの実行プログラム配置先のみです。

**現状の実装**: 共有フォルダは作成しません。

**→ SMB 共有の要否と、必要な場合は共有一覧をご提供ください。**

### C-1. データディスクの `disk_number`

`disk_number: 2` は「OS ディスク=0 / Azure 一時ディスク=1 / データディスク=2」を前提としています。
一時ディスクを持たない VM サイズ（Dv5 / Ev5 など）では **データディスクが 1 番**になります。

`win_disk` ロールは実行前に `Get-Disk` の結果を表示します。ずれている場合は
`group_vars` / `host_vars` の `data_disks[].disk_number` を修正してください。
併せて `azure_move_temp_drive: false` としてください。

### C-2. 日本語イメージ前提

概要 1.6「日本語を使用する」に対し、Azure Marketplace の日本語イメージを使用する前提で
`install_ja_language_pack: false` としています。英語イメージから構築する場合は
`inventory/group_vars/all/main.yml` で `true` に変更してください
（言語パックのダウンロードにインターネット接続が必要です）。

### C-3. MBR パーティションと 2TB の D: ドライブ

シート8「8.ﾃﾞｨｽｸの管理」は D: を **MBR / 2048GB** としています。
MBR の上限は 2TB（2048GB）であり、**ちょうど上限値**です。
将来 D: を拡張する予定がある場合は GPT を推奨します
（`data_disks[].partition_style` を `gpt` に変更）。

**→ 設計どおり MBR とするかご確認ください。**

### C-7. 適用済みパッチ

シート8「14.WindowsUpdate適用ﾊﾟｯﾁ一覧」は空欄です。
概要 1.14「構築時に最新版を適用する」に従い、`win_update` ロールは
**構築時点の最新**を適用します（KB 固定はしません）。
適用結果は証跡（`evidence/<ホスト名>_evidence.txt` の `HotFix`）に記録されます。

### C-8. 役割と機能の「既定でインストール済み」項目

シート8「12.役割と機能の追加」で ■ かつ「（ﾃﾞﾌｫﾙﾄ）」と注記されている項目
（.NET Framework 4.8 / BitLocker ドライブ暗号化 / Microsoft Defender ウイルス対策 /
Windows PowerShell 5.1 / Wireless LAN Service / WoW64 サポート / XPS Viewer /
システム データ アーカイバー / WindowsAdminCenterSetup / 拡張記憶域 /
ファイル サービスと記憶域サービス / 記憶域サービス）は OS 既定で導入済みのため、
`windows_features` には**含めず**、`windows_features_expected_default` に列挙して
証跡取得時に導入状態のみ確認します。

なお **`WindowsAdminCenterSetup`** は `Get-WindowsFeature` の標準的な機能名ではなく、
Windows Admin Center のインストーラを指している可能性があります。

**→ Windows Admin Center の導入要否をご確認ください（現状は導入しません）。**

### C-9. サービス一覧（シート8 16.）の扱い

シート8「16.ｻｰﾋﾞｽ一覧」は約 380 件のサービスの状態・スタートアップの種類の一覧ですが、
これは**構築後の実機状態を記録したもの**と解釈しています。
概要 1.15 で明示的に「無効にする」と指定されているのは
**`Hyper-V Time Synchronization Service`（`vmictimesync`）の 1 件のみ**のため、
`windows_services_config` にはこれのみを定義しています。

一覧には `Cortex XDR` / `Twistlock Defender` / `OpenSSH SSH Server` など
**本 Playbook では導入しないソフトウェアのサービス**も含まれています。

**→ 一覧の他のサービスについて、設計値として合わせ込む必要があるかご確認ください。**
