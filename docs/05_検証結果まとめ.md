## 3. 自動構築できなかった項目

### 3.1 2 項目とその理由

| 項目 | 直接の原因 | 本番での見込み |
| --- | --- | --- |
| 1.2 ドメイン参加 | 検証環境に Active Directory が無い | **実行可能**。`win_domain` は実装済みで、`enable_domain_join: true` に変えるだけ。ただし本番 AD での動作は未検証 |
| 1.13 タスクスケジューラ | 実行ユーザ `Administrator` が Azure VM に存在しない（組み込み管理者が無効化・改名される） | **要確認**。本番で `Administrator` が有効か、ドメイン修飾（`PICKLES-CORP\Administrator`）が必要かの確認待ち |

### 3.2 いずれも Ansible の制約ではない

2 項目とも **検証環境の条件**が原因で、Playbook の実装や設計の誤りではありません。
前者は AD を含む検証環境を用意できれば解消し、後者は本番環境のアカウント構成が
確定すれば解消します。

なお 2026-09-02 時点の別メンバ検証分（`Ansible対応可否一覧_20260902.md`）では
「Ansible そのものの制約で構築できないのは NIC チーミングと改ざん防止のみ」と
整理されていましたが、**今回の検証でもこの結論は変わりません**。

## 7. 本番構築への申し送り

検証で得た、**本番でも必ず効く**知見です。

### 7.1 環境差に起因するもの

| 項目 | 内容 |
| --- | --- |
| `Administrator` アカウント | Azure の Windows VM には存在しない。タスクスケジューラの実行ユーザ指定は本番環境で SID 解決できるか要確認（`docs/03` B-4） |
| ページファイル | Azure の Windows VM は既定で `D:\pagefile.sys`（一時ディスク）。ドライブ文字を変更する前に退避が必要 |
| 一時ディスクの有無 | `disk_number` は VM サイズに依存する。Dv5 / Ev5 など一時ディスクを持たない SKU ではデータディスクが 1 番になる（`docs/03` C-1） |
| OS 版数の表記 | Azure Marketplace イメージは `Windows Server 2025 Datacenter Azure Edition`。設計書の表記と一致しない |

### 7.2 実装上の作法

| 項目 | 内容 |
| --- | --- |
| PowerShell スクリプトの BOM | Windows へ配る日本語入り `.ps1` は **UTF-8 BOM 必須**。無いと CP932 と誤認され構文エラーになる |
| `default(D, true)` の扱い | 「falsy なら D」であり「未設定なら D」ではない。設計値 0 の項目には使わず `is none` で判定する |
| 突合せの期待値 | 設計書の値ではなく「その実行条件で期待される値」を置く。対象外にしたい項目は設計値を `-` にする |
| 環境固有の値 | 接続先 IP のように環境ごとに変わる値はインベントリ本体に置かない。`host_vars/<ホスト名>/connection.yml`（git 管理外）へ分離する |

### 7.3 運用上の注意

- **`PLAY RECAP` の `failed=` を必ず読む。** 「実行した」と「成功した」は別物で、今回一度見落として手戻りが発生しました。
- **`99_verify.yml` は既定で不一致を素通りさせる**（`verify_fail_on_mismatch: false`）。目視するか `-e verify_fail_on_mismatch=true` で流します。
- 以下 3 つは「一致」に見えても Ansible の成果ではありません。
  - コンピュータ名（Azure VM 名が元から一致）
  - 自動更新の無効化（Terraform の `patch_mode = "AutomaticByPlatform"` が Azure 側で設定）
  - タイムゾーン（イメージ既定値）
