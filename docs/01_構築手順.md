## 0. 今回のスコープ

今回の Ansible 初期構築は **検証機 1 台（`Ansible-TEST-FS`）** を対象とし、
以下を **対象外** とします。

| 対象外の項目 | 設計書 | 対象外とする方法 | 実施する場合 |
| --- | --- | --- | --- |
| ドメイン参加 | 概要 1.2 | `enable_domain_join: false` | `inventory/group_vars/all/main.yml` で `true` に変更 |
| タスクスケジューラ「SHM商品マスター更新」 | 概要 1.13 No.1 | 当該タスクに `skip: true` | `inventory/group_vars/fileserver.yml` の `skip` / `skip_reason` を削除 |

「SHM商品マスター更新」は設計書の起動日時が **2025/02/07 18:25**（過去日時）で
そのまま登録しても起動しないため、今回は登録しません
（`docs/03_要確認事項.md` A-5 参照）。

ドメイン参加を対象外としたことに伴う挙動:

- `playbooks/02_domain.yml` は **現状確認と時刻同期のみ** 実施します
- 本来ファイルサーバはドメインコントローラから自動同期（NT5DS）しますが、
  検証機はドメイン未参加で同期先が無くなるため、**検証機に限り**
  外部 NTP（`ntp.nict.jp,0x8`）と手動同期させています
  （`inventory/host_vars/Ansible-TEST-FS.yml` の `is_pdc_emulator: true`）
- 役割と機能（IIS / FTP / ファイルサーバ / FSRM）の**追加は実施** します
- FTP の基本認証ユーザ `docways` / `NPJS` は **ローカルユーザ**として作成します

## 2. 事前準備

### 2.1 制御ノード（Ansible 実行端末）

**方法A: Azure 上に実行用サーバを払い出す（推奨）**

`terraform/ansible-node` で検証用の Ansible 実行サーバ（Ubuntu）を払い出せます。
専用リソースグループに閉じ込めているため、`terraform destroy` で丸ごと作り直せます。
Ansible とコレクションは cloud-init で自動導入されます。

```bash

cp terraform.tfvars.example terraform.tfvars   # 運用端末のグローバル IP を設定
export ARM_SUBSCRIPTION_ID=$(az account show --query id -o tsv)
terraform init && terraform apply
terraform output ssh_command
```

詳細は [terraform/ansible-node/README.md](../terraform/ansible-node/README.md) を参照してください。

**方法B: 手元の Linux（WSL 可）に導入する**

```bash
python3 -m pip install --user "ansible-core>=2.16" pywinrm requests-ntlm
ansible-galaxy collection install -r requirements.yml
```

### 2.2 対象サーバ（1 回だけ実施）

Ansible から接続できるよう WinRM over HTTPS を有効化します。

```powershell
# RDP でログオンし、管理者権限の PowerShell で実行
.\terraform\scripts\bootstrap_winrm.ps1
```

Azure の Custom Script Extension / RunCommand から実行しても構いません。

### 2.3 データディスクの用意

設計書 シート8「8.ﾃﾞｨｽｸの管理」のとおり、**D: ドライブ（2048GB / MBR / NTFS）** が必要です。
FTP サイトの物理パス `D:\POD` / `D:\NPJS` とタスクの実行プログラムが D: 配下にあるため、
**Playbook 実行前に Azure 側でデータディスクをアタッチ**してください。

`win_disk` ロールが初期化・パーティション作成・フォーマットを行います
（Azure の一時ディスクが D: を占有している場合は Z: へ退避します）。

### 2.4 認証情報の設定

検証用の **仮値** を `inventory/group_vars/all/vault.yml` に設定済みです
（`.gitignore` によりリポジトリ管理外）。実機のパスワードに書き換えてください。

```bash
vi inventory/group_vars/all/vault.yml          # 仮値を実機の値へ書き換える
```

本番環境で使用する際は必ず暗号化します。暗号化後は各コマンドに
`--ask-vault-pass` を付与してください（仮値のまま＝平文の間は不要です）。

```bash
ansible-vault encrypt inventory/group_vars/all/vault.yml
```

## 4. 実行順序に関する注意

1. **データディスクは Playbook 実行前にアタッチする**
   FTP の物理パス（`D:\POD` / `D:\NPJS`）とタスクの実行プログラムが D: 配下です。
   D: が存在しないまま `03_role_setup.yml` を実行すると、
   FTP サイトの物理パスが誤った場所に作成されます（2.3 参照）。

2. **役割と機能の追加は FTP 設定より前**
   `win_ftp` ロールは冒頭で `Web-Ftp-Service` の導入状態を確認し、
   未導入なら明示的にエラーを返します。
   `site.yml` は `01_os_initial.yml`（役割追加）→ `03_role_setup.yml`（FTP）の順です。

3. **ドメイン参加は DC 構築の後**（今回はスコープ外）
   `enable_domain_join: true` にする場合、`02_domain.yml` は
   `dc` グループ → メンバーサーバの順で実行されます。
   ファイルサーバはメンバー参加のみで、DC 昇格は行いません。

4. **ドメイン参加後は接続ユーザの見直しが必要**
   ドメイン管理者で接続する場合は `inventory/group_vars/windows.yml` の
   `ansible_user` / `ansible_password` を
   `vault_domain_admin_user` / `vault_domain_admin_password` に切り替えてください。

5. **時刻同期はドメイン参加の有無で変わる**
   ドメイン参加後は自動同期（NT5DS）に戻す必要があります。
   検証機の `is_pdc_emulator: true`（外部 NTP と手動同期）は
   **ドメイン未参加の間だけの暫定設定**です。ドメイン参加を有効化する際は
   `inventory/host_vars/Ansible-TEST-FS.yml` の `is_pdc_emulator` を `false` に戻してください。

6. **UAC 無効化・Defender 無効化は再起動後に有効**
   `01_os_initial.yml` の最後に再起動を行います。

## 8. お引渡し

概要 1.2 のとおり、S-AZR-003〜006 は **OS 初期設定およびドメイン参加後に
アプリベンダー様へお引渡し** します（今回のスコープ外）。

また、セキュリティソフト（Cortex XDR）の導入はお客様にて実施いただく想定です
（概要 1.11）。本 Playbook は Defender をローカル GPO で無効化するのみです。
